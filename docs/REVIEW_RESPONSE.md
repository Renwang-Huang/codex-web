# Gemini 审查核对与迭代记录

核对日期：2026-10-28。原始报告归档为 [PROJECT_REVIEW.md](archive/PROJECT_REVIEW.md)，个人目录已替换为示例。结论以当时源码、自动化回归、隔离 HTTP/浏览器检查及只读本地索引测量为依据；评分和定性赞誉不作为验收证据。后续发布范围见 [验收记录](ACCEPTANCE.md)。

## 缺陷逐项判断

| 报告条目                              | 判断                         | 本轮处理                                                                                                                                                                               |
| ------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1 SSE 引发全量请求                  | 成立，优先修复               | Token 增量直接推送，带消息编号和字符偏移，避免与详情响应交叠后重复拼接。其他通知按会话刷新详情。列表采用白名单摘要；扫描时间、RSS 或排序单独变化不触发整表刷新。页面每 30 秒兜底核对。 |
| 2.2 无条件扫描与缓存残留              | 部分成立                     | 历史目录和非活动文件改为 30 秒核对；新活动日志立即纳入，每 4 秒增量读取；显式新建、归档、恢复会使目录缓存失效；已消失路径在核对时驱逐。保留进程归属检查。                              |
| 2.3 指令历史无界                      | 成立，但不能直接删除请求身份 | 保留最近 100 条完整已结束指令；全部 pending、queued、sending、uncertain 记录保留。旧已结束记录移至不含正文的去重凭据，先落凭据再删正文，重启后仍拒绝重复执行和更换正文复用编号。       |
| 2.4 快捷键并发                        | 成立                         | 前端按会话锁定提交，快捷键及 requestSubmit 均检查；刷新不解锁，发送期间的新草稿不被成功响应清空。后端同时覆盖首次持久化前的准备窗口，排队指令不能越过正在准备的直接发送。              |
| 2.5 相同回复被去重                    | 成立                         | 按 turnId/itemId 合并官方轮次，包含 userMessage，不跨轮次按全文去重；本地相邻重复表示仅在同轮次合并，并补齐最终回复标记。                                                              |
| 2.6 HTTPS 无 Secure 就不能清除 Cookie | 规范推断错误                 | HTTPS 下不带 Secure 的同名、同路径 Cookie 也能覆盖并删除原 Cookie。仍将登录、退出属性统一，作为一致性维护。                                                                            |
| 2.7 认证审计缺失                      | 成立                         | 记录登录成功、密钥错误、无效请求、限流及退出；保留可信代理解析出的地址，不记录访问密钥、Cookie 或请求正文。                                                                            |

关于 2.2：原实现确实读取每个 PID 的 `status`，但 `exe`、`environ`、`fd` 只读取识别出的 Codex 候选进程；报告把扫描范围描述得过宽。23 小时内累计 23 分钟 CPU、248 MB 内存的历史观测未在本轮复现，也不足以单独归因于扫描。当前不取消 `/proc` 检查，因为它参与防止接管仍被终端持有的会话。

关于 2.6：[HTTP Cookie 规范草案的存储算法](https://httpwg.org/http-extensions/draft-ietf-httpbis-rfc6265bis.html#name-storage-model)对非安全 Cookie 覆盖 Secure Cookie 的限制包含连接不安全这一条件。隔离浏览器在合成 HTTPS 域名上，先设置 Secure Cookie，再用不含 Secure 的过期 Set-Cookie，实际观察到 Cookie 被清除。因此拒绝将原报告中的规范断言作为真实缺陷。

## 体验建议

已实现 Markdown、代码高亮、复制回复原文和代码、浏览器返回/前进及刷新恢复会话、输入框自适应、系统深色主题、最近目录建议、唤醒刷新和日志 Token 用量。

复用 [Marked](https://marked.js.org/)、[DOMPurify](https://github.com/cure53/DOMPurify) 与 [Highlight.js](https://github.com/highlightjs/highlight.js)。原始 HTML 转义后，渲染结果再经元素和属性白名单净化；不加载回复中的远程图片。模块和许可证由锁定的 npm 依赖复制到本地静态目录，保持现有 CSP，不引入外部 CDN。复制内容不包含新增的复制按钮或时间戳；可信局域网 HTTP 提供传统复制回退。

“标题永久来自首次 Prompt”的说法不准确：原有 live 读取已经优先采用 `thread.name`。网页尚无重命名入口，这属于新增功能；本轮没有扩展官方命名与本地历史索引的同步协议。

Token 显示区分累计用量、最近请求和窗口上限，不将累计 Token 当成上下文占用率，也不推测未记录的值。

## 验证与测量

服务端回归覆盖已有状态、队列、断线、归档、模型配置，以及新增的增量通知、消息合并、准备窗口锁、历史压缩、持久去重、目录缓存和认证审计。

浏览器检查使用独立 HTTP/SSE 模拟服务和 Microsoft Edge，不读取访问密钥，不向真实 Codex 会话发送指令：

- 80 次真实 EventSource 增量引发 **0 次 snapshot、0 次 detail 请求**，重复的偏移范围不会重复拼接。该计数用于隔离 Token 触发行为；正常列表变化、重连和 30 秒兜底仍会读取。
- 连续快捷键与直接 requestSubmit 只产生一次提交，发送期间刷新不解锁，新草稿保留。
- 检查 Markdown 结构、高亮、恶意 HTML/链接过滤、复制内容与 HTTP 回退。
- 检查 390px 手机布局、返回/前进、刷新恢复选中、唤醒核对和深色主题，保存并人工查看桌面与手机截图。
- 浏览器实测 Cookie 规范反例；隔离后端实测 HTTPS/LAN Cookie、认证审计、限流和退出后 SSE 关闭。

同一份实际本地日志索引的测量（295 个会话、5 个活动日志）：

| 测量                                  | 结果                         |
| ------------------------------------- | ---------------------------- |
| 原列表投影 JSON                       | 764,159 字节                 |
| 新白名单列表 JSON                     | 384,375 字节，减少约 49.7%   |
| 热缓存仍核对全部目录及 stat，5 次均值 | 11.17 ms/次，CPU 11.24 ms/次 |
| 复用目录及非活动缓存，5 次均值        | 0.223 ms/次，CPU 0.205 ms/次 |

以上大小只对比会话列表 JSON，未计压缩与 HTTP 开销；扫描计时只覆盖 SessionIndex，不覆盖 `/proc`、RPC、完整 Hub 或长期常驻资源，不作为长期 CPU/内存收益证明。机器负载、会话数量和日志增长都会影响结果。

复现命令：

```bash
npm ci
npm test
npm run test:review-browser
```

本地检查产物位于 `.local/checks/review-browser.json`、`review-metrics.json` 和 `review-*.png`。没有重启现有工作台服务、上传公网静态资源、创建模型轮次、归档用户会话或修改本地现有指令状态；本轮是本地候选实现与验证，不是线上验收。

运行时状态仍有边界：旧去重凭据和审计日志继续增长；未解决指令不自动淘汰；外部创建或移动的非活动历史文件可能最多延迟约 30 秒显示。升级后备份应同时保存 `state.json` 和 `command-receipts/`。原版本不会读取压缩凭据，直接降级会失去旧请求的去重能力；回退前需要恢复完整的原始指令台账或使旧版本读取这些凭据，不能只替换源码或恢复一个不含旧请求身份的 state.json。
