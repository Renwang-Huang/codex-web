## 关键回归

- 分支 rollout 可能在自身元数据后嵌入父线程元数据。现在保留本文件的首条身份记录，避免 26 个历史子任务被错误合并。
- 新建、尚未收到第一条输入的 loaded thread 可能尚无 rollout。对它先 `thread/resume` 会报 `no rollout found`。现在保留 `thread/start` 的自动订阅，直接发送首次输入；已经加载且无持久化路径的线程也不执行冷续接。初次失败记录保存在 `.local/checks/api-smoke-initial-failure.json`，修复后真实两轮接口验收通过。
- 写请求的结果未知时，保留状态且不自动重发；同一工作台请求编号重复提交只发出一次模型请求。取消的队列记录不再发送。
- 独立终端的状态与控制能力解耦。原来的头尾窗口会遗漏长任务中间的 `task_started`，而缺少共享控制连接又会覆盖为待确认。现在只对活动日志建立完整增量索引；大日志中间的当前轮和计划、跨 UTF-8 字符及未完整写入的追加记录均有回归覆盖。
- 原生队列写响应丢失后通过消息编号只读核对；队列消失本身不当作成功。撤回调用真实队列删除接口；会话后续转为共享控制时，中断也会删除遗留的原生队列条目。回归中禁止对独立终端冷续接、`turn/start` 和终端输入。

## 未覆盖与现有限制

- 手机浏览器采用 Chromium 手机视口模拟，并已检查实际渲染截图；没有拿真实 iPhone 或 Android 设备进行网络和触控验收。
- 没有实际触发并批准高权限命令、文件修改或请求用户输入；审批/问答界面已实现，但真实审批链路尚待日常使用验证，不能称为已通过完整审批验收。
- 没有对正在工作的用户会话执行中断或注入消息。中断接口使用官方轮次编号；本轮没有实机验证真实用户任务的中断结果。
- 实机断网、主机断电和恶意同用户竞争未做破坏性测试；连接中断和进程重启时的结果未知语义由隔离回归验证。
- 独立终端在当前版本可通过原生队列接收下一轮任务，即时补充和中断仍在原终端处理。不支持实验性队列的版本保留监控与退出后续接行为；没有逐个实测其他 CLI 版本及各类旧历史记录。
- `turn/start` 的空闲检查存在跨客户端竞争窗口。当前实现没有把非原子检查包装成严格的全局串行保证。
- 进程、会话数量随运行变化；不把快照计数当成恒定值。`本轮完成` 不等于整个用户目标完成。
